# Claude Code delegation contract

Use this contract for `Agent` calls in pstack skills and playbooks. It targets Claude Code v2.1.251 or newer for model precedence. Check `claude --version` when exact model routing matters; v2.1.250 and earlier give `CLAUDE_CODE_SUBAGENT_MODEL` precedence over an invocation or agent definition.

## Dispatch and capacity

`Agent` starts a new subagent. A completed subagent has finished its run; it is not silently running because it once had children. Save the returned agent ID. Use `SendMessage` with that ID to continue its context or correct its work, including after a completed run. A new `Agent` call starts fresh. Use `TaskStop` only to cancel work that should stop; confirm cancellation before reassigning a conflicting writer. A subagent stopped by the user in `/tasks` cannot be resumed by `SendMessage` until the user resumes it.

Treat N in a swarm, arena, or reviewer roster as the total required work, not simultaneous capacity. Before dispatch, leave room for other running agents in this session and select a window no larger than the available session capacity. Claude Code defaults to 20 concurrent `Agent` subagents; `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` changes that limit, and running subagents, forks, and resumed agents within this session can occupy slots. Launch up to the window and refill each free slot as a result arrives until the queue is exhausted. If a call reports `Concurrent subagent limit reached`, keep that item queued and retry after a slot frees; do not count it as a worker dropout or silently shrink N. A worker that starts and then fails is a separate failure to report or retry under the workflow's rule. Give concurrent repository writers separate worktrees and ownership boundaries. For independent non-repository artifacts, separate output directories suffice.

## Model and effort

On v2.1.251 or newer, model precedence is the invocation's `model`, the agent definition's `model`, `CLAUDE_CODE_SUBAGENT_MODEL`, then the parent model. `auto` in a pstack model sheet means leave the invocation model unset and accept that runtime resolution; it does not promise the parent model. `inherit-parent` requests the actual parent model: route general roles to shipped `pstack:inherit`, full poteto coordinators to `pstack:poteto-agent-inherit`, and bounded poteto work to `pstack:poteto-worker-inherit`, with invocation `model` omitted. Append `-<level>` to the selected type for an effort override. These definitions set `model: inherit`. Do not pass the sheet tokens `auto` or `inherit-parent` as model slugs. On v2.1.250 and earlier, an environment override may defeat either choice; check the effective model and report when exact inheritance cannot be assured. On v2.1.257 or newer, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` can override both definition and invocation. A family alias may resolve to the parent's exact model when it is already in that family; otherwise it resolves according to Claude Code's alias rules. A configured model can also be substituted by an organization allowlist or fallback chain.

Effort comes from a supported agent definition's `effort` frontmatter. An effort agent changes requested effort, while an invocation model (when supplied) still chooses the requested model. Without an agent effort override, the session's effort applies. `CLAUDE_CODE_EFFORT_LEVEL` overrides both session settings and skill or subagent frontmatter. The model's available levels, a managed `maxEffortLevel`, or an organization effort cap can lower the effective level. Do not claim that a requested model or effort definitely ran. For consequential comparisons, check `/tasks` for the actual model and indicated effort (Claude Code v2.1.242+), and report uncertainty if the runtime does not expose it.

## Tools and research boundaries

There is no `readonly` argument on the Claude Code `Agent` tool. Ask a research worker to make no writes. For a strict code-only reader, use an agent definition that allowlists read tools such as `Read`, `Grep`, and `Glob`. Removing `Write`, `Edit`, or `NotebookEdit` alone is not a strict read-only boundary while `Bash` or write-capable MCP tools remain. Keep MCP access for evidence investigators that need it, and state the no-write task constraint; a restrictive allowlist that excludes MCP would block that work.

Background agents retain MCP tools but only a documented subset of built-in tools. Do not promise full tool access or require a filtered tool in a background task. If a required tool is missing, run that step in a supported foreground context or perform it in the coordinator. Foreground/background choice can also depend on fork mode, session settings, and agent-team context.

Sources: [Claude Code subagent documentation](https://code.claude.com/docs/en/sub-agents) for model order, tools, capacity, and resume behavior; [model configuration](https://code.claude.com/docs/en/model-config) for effort precedence and caps.
